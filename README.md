# am-secrets

Локальный менеджер секретов для macOS. Команда `secrets` импортирует выбранные поля из Bitwarden, хранит их в зашифрованном виде и передаёт конкретному скрипту через переменные окружения. Фоновая служба `secrets-daemon` держит ключ и сеанс Bitwarden в памяти до блокировки.

## Установка из исходников

Понадобятся macOS, Xcode Command Line Tools со Swift 5.9 или новее, Rust 1.89 или новее с Cargo и Bitwarden CLI (`bw`) в `PATH`. Для примера и интеграционных тестов нужен Python 3.9 или новее. При первой сборке Cargo может загрузить зависимости.

Клонируйте репозиторий или распакуйте архив исходников из раздела Releases. Если Bitwarden требует двухфакторное подтверждение или проверку нового устройства, войдите в выбранный аккаунт через `bw login` в терминале. Перед первым входом задайте явный URL командой `bw config server URL`. Для облака США это `https://vault.bitwarden.com`, для ЕС — `https://vault.bitwarden.eu`.

Некоторые ранее настроенные профили Bitwarden возвращают `serverUrl: null` в `bw status`. В таком случае CLI не может проверить адрес. Если нужно сохранить старый профиль, задайте отдельную переменную `BITWARDENCLI_APPDATA_DIR` и используйте её для `bw`, установщика и последующих команд `secrets`. Настройте сервер и войдите в новый профиль. Порядок настройки профилей описан в [справке Bitwarden](https://bitwarden.com/help/cli/#log-in-to-multiple-accounts).

Откройте терминал в каталоге с `install.sh` и запустите установку.

```sh
bash install.sh
```

Установщик собирает и подписывает обе программы на вашем Mac, запускает службу через `launchd` и добавляет `~/.secrets` в `PATH` для zsh. При первой установке он запускает `secrets setup`. Выберите Bitwarden, укажите адрес сервера и email аккаунта, затем введите мастер-пароль в терминале.

Откройте новый терминал или выполните `source "${ZDOTDIR:-$HOME}/.zshrc"`. В другой оболочке добавьте `$HOME/.secrets` в её `PATH`. Проверьте установку.

```sh
command -v secrets
secrets --version
secrets status
```

При уже настроенном хранилище используйте `secrets unlock`. Сборку можно проверить отдельно командой `bash install.sh --build-only`.

## Запуск скрипта с одним полем

В примере `Demo App` — имя записи в Bitwarden, `token` — имя её поля, `./app.py` — существующий скрипт. Подставьте свои имена и путь.

```sh
secrets add 'Demo App:token' --file ./app.py
secrets wrap --file ./app.py --use 'Demo App:token' -- python3
```

Первая команда импортирует поле и разрешает выдачу этому файлу. Она запрашивает мастер-пароль, даже если сеанс открыт. Вторая передаёт значение скрипту в переменной `DEMO_APP_TOKEN`. При ошибке авторизации или доступа скрипт не запускается.

Для повторных запусков можно добавить свою именованную функцию в `~/.zshrc`. Укажите полный путь к тому же файлу, которому вы дали доступ, и загрузите настройки через `source "${ZDOTDIR:-$HOME}/.zshrc"`.

```sh
run_demo() {
  command secrets wrap --file "$HOME/demo-app/app.py" --use 'Demo App:token' -- python3 "$@"
}
```

`run_demo` передаёт свои аргументы скрипту. Функция появляется в оболочке после того, как вы сами добавите её в настройки.

## Повседневные команды

```sh
secrets ls       # показать имена записей без значений
secrets sync     # обновить подключённые поля из Bitwarden
secrets status   # проверить сеанс и состояние обновлений
secrets lock     # очистить ключ и сеанс из памяти службы без обращения к Bitwarden
secrets unlock   # снова открыть сеанс
```

Запущенный скрипт получает секрет в открытом виде и может вывести или сохранить его. Правила путей и список разрешённых программ ограничивают штатную выдачу. Процессы, работающие от вашего имени, могут менять скрипты и настройки. Блокировка закрывает последующую выдачу, а уже запущенные программы сохраняют полученное окружение.

## Проверки и документация

```sh
cargo test --locked --manifest-path secrets-cli/Cargo.toml
cargo build --locked --manifest-path secrets-cli/Cargo.toml
swift test --package-path secrets-daemon
swift build --package-path secrets-daemon
codesign -s - --force secrets-cli/target/debug/secrets
codesign -s - --force secrets-daemon/.build/debug/secrets-daemon
python3 tests/installer.py
python3 tests/daemon-cli.py
```

Сквозная проверка использует подставной Bitwarden CLI, синтетические записи и отдельный демон во временном каталоге. Дополнительные сценарии в `tests/` проверяют миграцию, правила файлов и перенос списка полей.
