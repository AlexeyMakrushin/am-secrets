# Архитектура am-secrets

Rust CLI отвечает за авторизацию, синхронизацию, зашифрованное хранилище и запуск программ. Swift-демон хранит открытый сеанс в памяти и проверяет подпись клиентов. Оба компонента используют протокол версии 2.

## Путь команды

1. CLI разбирает аргументы. Блокировка, справка и версия обходятся без обращения к Bitwarden.
2. Для остальных пользовательских команд с профилем Bitwarden CLI выполняет `bw sync`. При ошибке `add`, `sync` и `manifest apply` завершаются. Другим командам может быть доступен локальный снимок.
3. Операции с хранилищем используют файловую блокировку для согласования параллельных изменений.
4. CLI вычисляет идентификатор хранилища по пути `keys.json`, обёртке ключа, имени провайдера и параметрам аккаунта. Идентификатор хранится как SHA-256.
5. Демон сверяет идентификатор и возвращает открытый сеанс доверенному клиенту. Когда нужно открыть сеанс, CLI проверяет введённый в терминале мастер-пароль, расшифровывает локальное хранилище и получает сеанс провайдера. Ключ и сеанс передаются демону.
6. Локальное чтение может продолжаться с открытым сеансом без сети. Для получения новых значений нужна действительная сессия провайдера.
7. Команды записи собирают результат в памяти и сохраняют зашифрованный снимок атомарно.

## Локальные файлы

| Файл в `~/.secrets` | Назначение |
|---|---|
| `vault.enc` | Зашифрованные значения и правила выдачи |
| `keys.json` | Ключ хранилища, зашифрованный ключом, полученным из мастер-пароля |
| `config.yaml` | Провайдер, список разрешённых программ и настройки сокета |
| `trusted_hashes` | Список доверенных подписей клиентских программ |
| `sync-status.json` | Время последнего успешного `bw sync` и признак ошибки |
| `local-sync-status.json` | Состояние и время фонового обновления локального снимка |
| `.command.lock`, `.background.lock` | Блокировки команд и фонового процесса |

Атомарная запись использует временный файл с правами `0600` в каталоге назначения, `fsync` и `rename`. Установка оборванной символической ссылки на месте файла приводит к ошибке записи. ОС освобождает файловую блокировку при завершении процесса.

## Протокол 2

Сообщения передаются через Unix-сокет с правами `0600`. Формат сообщения состоит из четырёх байтов длины в порядке big-endian и тела JSON. Команды протокола включают `PING`, `GET_STATE`, `SET_STATE`, `CHECK_SESSION`, `CLEAR_STATE` и `RETIRE_LEGACY_PIN`. Клиентская подпись проверяется для всех команд, кроме `PING`. CLI и демон обновляются вместе.

Структура `SessionStore` защищена мьютексом. Ключ и сеанс в долговременной памяти демона помещаются в область с `mlock` и очисткой при освобождении. Границы защиты описаны в [SECURITY.md](SECURITY.md).

`SECRETS_HOME` и `SECRETS_SOCKET` позволяют тестам запускать отдельные экземпляры с собственными файлами и сокетом. Тесты дополнительно подставляют Bitwarden CLI. Keychain остаётся общим для запущенных от имени одного пользователя экземпляров.

## Правила выдачи и перенос

`AccessPolicy` хранит для каждой записи и поля набор полных путей. Отсутствующее правило разрешает явный запрос. Пустой набор закрывает выдачу. Правило переживает удаление и повторный импорт значения. Унаследованные правила по имени программы действуют как дополнительный фильтр до `access reset-legacy`.

`wrap` преобразует `--use` в точные ссылки на поля. Путь из `--file` приводится к полному с разрешением символических ссылок. CLI очищает окружение от прежней выдачи, передаёт запрошенные поля и освобождает блокировку перед запуском. Интерпретатор получает путь файла первым аргументом, затем получает аргументы пользователя. Запуск проходит напрямую через системный API и возвращает код завершения программы.

Изменения правил через `add --file`, `access revoke`, `access open`, `access reset-legacy`, `move` и `manifest apply --with-access` требуют свежего мастер-пароля с проверкой локального ключа и хранилища.

Manifest версии 2 содержит правила файлов. Импорт ограничен обычным файлом размером до 1 МиБ. CLI проверяет совпадение источника с настройками, структуру и дублирующиеся ключи JSON. Без `--with-access` сохраняются местные правила. Manifest версии 1 позволяет применять только поддерживаемые им старые правила. `--dry-run` проверяет метаданные после `bw sync` без получения ключа или значений.

## Фоновое обновление

После подходящей успешной команды CLI планирует обновление отдельным процессом со стандартными потоками, направленными в `/dev/null`, и своей группой процессов. Процесс получает ключ и токен через демон. Переменные предыдущей выдачи удаляются из его окружения.

Файловая блокировка допускает один фоновый процесс на хранилище. `local-sync-status.json` ограничивает запуск одним разом в минуту и хранит итог и время. Процесс берёт блокировку команд для чтения снимка и записи результата. Сетевой этап проходит без блокировки команд.

Перед записью процесс сверяет шифротекст, ключи, конфигурацию и случайный маркер открытого сеанса. CLI меняет маркер при разблокировке с вводом пароля и при блокировке. Если в ходе обновления изменились исходные данные или сеанс, либо одно из полей получить не удалось, сохраняется прежний снимок. Фоновый процесс использует только уже открытый сеанс, а обновление планируется при вызове команд CLI.
