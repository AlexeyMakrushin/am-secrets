# Команды am-secrets

| Команда | Действие |
|---|---|
| `secrets setup` | Создать новое хранилище и открыть сеанс |
| `secrets unlock` | Открыть сеанс |
| `secrets lock` | Очистить ключ и сеанс из памяти службы |
| `secrets status` | Показать состояние службы, сеанса и обновлений |
| `secrets ls [ITEM]` | Показать имена записей или полей |
| `secrets get ITEM FIELD`, `secrets ls ITEM FIELD` | Напечатать значение в терминале |
| `secrets add ITEM [FIELD]` | Импортировать отсутствующие поля |
| `secrets add ITEM:F1,F2 --file FILE [--file OTHER]` | Импортировать выбранные поля и разрешить их выдачу указанным файлам |
| `secrets add ITEM --file FILE` | Привязать текущие локальные поля записи. Если записи нет, импортировать её |
| `secrets wrap --file FILE --use ITEM:F1,F2 OTHER:F3 -- python3 [ARGS]` | Запустить `python3 FILE ARGS` и передать выбранные поля в окружение |
| `secrets wrap --file EXECUTABLE --use ITEM:FIELD` | Запустить файл напрямую, если он исполняемый и разрешён в настройках |
| `secrets sync [ITEM [FIELD]]` | Обновить подключённые поля из Bitwarden |
| `secrets delete ITEM [FIELD]` | Удалить локальную копию записи или поля и сохранить правила файлов |
| `secrets move OLD NEW` | Перенести разрешения со старого пути на новый. Файлы на диске остаются на своих местах |
| `secrets access show` | Показать правила файлов и состояние прежних ограничений по имени программы |
| `secrets access revoke ITEM:FIELDS --file FILE [--file OTHER]` | Отозвать доступ у указанных файлов |
| `secrets access open ITEM:FIELDS` | Снять ограничения по путям для выбранных полей |
| `secrets access reset-legacy` | Снять прежние ограничения по имени программы |
| `secrets manifest export FILE` | Экспортировать список записей, полей и правил в новый JSON-файл |
| `secrets manifest apply FILE [--dry-run] [--with-access]` | Импортировать поля из Bitwarden по списку |
| `secrets trust --self [--clean]` | Добавить подпись текущего CLI в список доверенных клиентских программ. `--clean` удаляет прежние подписи |

## Выдача полей

В одном `--use` можно указать несколько записей через пробел и несколько полей одной записи через запятую. Имена с пробелами заключайте в кавычки, например `--use 'Demo App:token,user id'`. Двоеточие и запятая зарезервированы для синтаксиса выбора полей. Для выдачи полей нужны `--use` и `--file`.

am-secrets сопоставляет полный путь с разрешёнными после разрешения символических ссылок. Интерпретатор или исполняемый файл должен входить в список разрешённых программ в настройках. Аргументы после имени интерпретатора передаются скрипту. Запуск модулей через `-m` и флаги интерпретатора перед путём к файлу этим интерфейсом не поддерживаются.

Имена переменных окружения формируются из записи и поля. Например, `Demo App:token` превращается в `DEMO_APP_TOKEN`. Повторяющиеся и зарезервированные имена приводят к ошибке. Перед запуском из окружения убираются имена подключённых полей, переменных предыдущей выдачи, `BW_SESSION` и `BW_PASSWORD`.

Поле без правила доступно по явному запросу любому подходящему файлу. Отзыв последнего пути оставляет правило, запрещающее выдачу всем. При удалении и повторном импорте поля правило сохраняется. Команды `add --file`, `access revoke`, `access open`, `access reset-legacy` и `move` требуют свежего мастер-пароля.

Для переноса разрешений используйте, например, `secrets move ./old/app.py ./new/app.py`, затем обновите путь в `wrap --file`. Старый файл может уже отсутствовать. Чтобы сохранить доступ по обоим путям, добавьте новый через `secrets add ITEM:FIELDS --file NEW`.

## Синхронизация

Перед обычной командой с профилем Bitwarden выполняется `bw sync` с тайм-аутом 20 секунд. При ошибке `add`, `sync` и `manifest apply` прекращают работу. Локальное чтение может использовать прежний снимок. `lock`, справка и `--version` работают без обращения к Bitwarden.

После успешных команд CLI может запустить фоновое обновление локального снимка. Для `wrap` оно начинается после успешного завершения программы. Фоновое обновление использует открытый сеанс и запускается максимум раз в минуту на хранилище. `lock`, `setup`, `trust`, `whitelist`, ручной `sync` и `manifest apply --dry-run` его пропускают.

| Строка статуса | Значение |
|---|---|
| `Latest bw sync: successful` | Обновлён кэш самого Bitwarden CLI |
| `Prepared: N, Errors: 0` и код 0 после ручного `sync` | Выбранные обновления успешно применены |
| Фон `success` | Фоновый снимок записан |
| Фон `failed` | Фоновая попытка завершилась ошибкой, прежние значения сохранены |
| Фон `superseded` | Во время получения данных изменилось хранилище, конфигурация или сеанс. Запись отменена |
| Фон `running` | Снимок ещё обновляется |

Ручное и фоновое обновления имеют отдельные результаты. После успешного ручного `sync` может по-прежнему отображаться прежняя ошибка фона.

### Удаление пропавших записей и полей

Ошибка `provider_item_missing` означает, что в Bitwarden пропала запись, а `provider_field_missing` указывает на отсутствующее поле. Фон сообщает имя записи или поля и сохраняет локальный снимок. При ручном `sync` просмотрите список пропавших полей. Если с ним согласны, подтвердите локальное удаление в терминале. Enter отменяет всю запись обновлений. Сетевые ошибки, тайм-ауты, неверная сессия и некорректные ответы Bitwarden прерывают синхронизацию без предложения удалить данные.

`secrets sync` проверяет все подключённые записи, `secrets sync ITEM` ограничивается одной записью, а `secrets sync ITEM FIELD` проверяет одно поле. Подтверждение относится ко всему показанному списку. Удаления и обновления записываются вместе.

`secrets delete ITEM [FIELD]` сразу удаляет локальные значения при открытом сеансе. Если удалить последнее поле отдельно, пустая запись остаётся. Чтобы убрать и саму запись, выполните `secrets delete ITEM`. Bitwarden этими командами не изменяется. Повторно подключить поле можно через `add` или `manifest apply`, пока оно существует в Bitwarden.

## Перенос списка полей

Экспортируйте список на исходной машине.

```sh
secrets manifest export ./secrets-manifest.json
```

На другой машине с тем же настроенным аккаунтом Bitwarden сначала проверьте список, затем импортируйте его.

```sh
secrets manifest apply ./secrets-manifest.json --dry-run
secrets manifest apply ./secrets-manifest.json
```

JSON содержит сервер, email, имена полей и правила доступа. Значения, ключи и сеансы в него не попадают. Экспорт создаёт новый файл с правами `0600`. Значения на целевой машине загружаются из Bitwarden. `--dry-run` проверяет список без разблокировки и чтения значений, сохраняя предварительный `bw sync`.

Обычный импорт сохраняет местные правила и поля вне списка. `--with-access` заменяет правила по данным файла и требует свежего мастер-пароля. Пути из manifest версии 2 должны существовать на машине назначения. Manifest версии 1 сохраняет местные правила файлов даже с `--with-access`. Список разрешённых программ при импорте остаётся прежним.

## Коды возврата

| Код | Значение |
|---|---|
| `0` | Успех |
| `1` | Общая ошибка, отсутствующая запись или закрытый сеанс |
| `2` | Неверные аргументы |
| `3` | Ошибка связи со службой |
| `4` | Подпись CLI отсутствует в списке доверенных |
| `5` | Ошибка ключа, зашифрованного хранилища или записи |
| `6` | Ошибка Bitwarden |
| `7` | Ошибка настроек или отсутствие терминала |
| `10` | Запрошена служебная запись |

`wrap` возвращает код запущенной программы. При завершении по сигналу код равен 128 плюс номер сигнала.

Подробнее о границах выдачи и хранения см. [Безопасность](SECURITY.md).
