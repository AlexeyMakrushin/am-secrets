# Безопасность am-secrets

## Локальное хранилище и сеанс

Хранилище шифруется AES-256-GCM со случайным 256-битным ключом. Ключ шифруется ключом, полученным из мастер-пароля через PBKDF2-SHA256 с 600 000 итераций. Мастер-пароль вводится в терминале и используется при разблокировке. При обращении к Bitwarden CLI получает его во временной переменной окружения дочернего процесса через `--passwordenv`.

Демон хранит ключ и сеанс до `secrets lock`, остановки службы или перезагрузки. Он держит их в выделенной памяти с `mlock` и очищает её при освобождении. Временные копии в Swift, JSON, Bitwarden CLI и ОС находятся вне этой гарантии.

Демон принимает соединения через Unix-сокет с правами `0600`. Для команд управления сеансом он проверяет доверенную подпись клиента по CDHash. При выдаче ключа и сеанса он проверяет идентификатор хранилища. Защита рассчитана на штатный доступ к локальному хранилищу. Процесс с правами вашего пользователя может менять список доверенных подписей, конфигурацию, CLI или разрешённый скрипт. Администратор и отладчик могут иметь доступ к памяти.

## Выдача секретов скриптам

`wrap` проверяет полный путь файла и список разрешённых программ. Для выбранных полей он формирует переменные окружения и передаёт их целевому процессу. Скрипт получает значения в открытом виде и может сохранить их, вывести или передать дочерним процессам. Уже запущенные программы сохраняют полученное окружение после `secrets lock`.

Программа устанавливает соответствие по пути и разрешает символические ссылки. Содержимое файла и его импорты могут измениться после назначения. Подтверждение свежим паролем защищает изменение правил через штатный интерфейс. Ограничения по каталогам из старых конфигураций игнорируются.

Поле без правила доступно по явному запросу. Отзыв последнего разрешённого пути закрывает выдачу всем, а удаление значения сохраняет правило поля. Команды `get` и `ls ITEM FIELD` выводят открытое значение в терминал. Проверка TTY снижает риск случайного фонового вызова. Для запуска программ используйте `wrap`.

Перед `wrap` CLI удаляет из унаследованного окружения переменные, соответствующие подключённым полям, и переменные, перечисленные в `SECRETS_INJECTED`. Копии значений под другими именами остаются доступны. Зарезервированные управляющие имена и совпадения имён переменных отклоняются.

## Перенос и восстановление

Экспортированный manifest содержит метаданные. Среди них имена записей и полей, сервер, email и правила доступа. Значения и ключи остаются в зашифрованном хранилище. `manifest apply --with-access` применяет правила из файла. Проверка структуры файла подтверждает его формат, поэтому происхождение и правила перед применением следует проверить отдельно.

Храните резервные копии `keys.json` и `vault.enc` как согласованную пару. Для восстановления из Bitwarden без локального ключа нужны новое локальное хранилище и повторный импорт полей. Manifest помогает восстановить список.

При переходе со старого хранилища с PIN команда `unlock` проверяет мастер-пароль и расшифровку, удаляет старую запись из Keychain, затем атомарно обновляет `keys.json`. При ошибке записи доступ по мастер-паролю сохраняется. Следующий `unlock` повторит миграцию. Пользовательские резервные копии старых ключей могут содержать PIN-обёртку и требуют отдельной защиты.

Тесты миграции используют подставной демон. Keychain привязан к пользователю macOS и остаётся доступен при смене `HOME`.
