# secrets — программа am-secrets

## Рабочий порядок

1. Проверь `secrets --version`. Ниже описан CLI 3.4.1; на старой версии сначала согласованное обновление. Проверь также `command -v secrets`: в агентском PATH может оказаться старый бинарь. Если версия отличается, используй проверенный `$HOME/.secrets/secrets`; это не разрешение обходить правила старой версией.
2. Определи исполняемый файл и минимальный список нужных полей по коду/настройке приложения. Для имён используй `secrets ls [ITEM]`, для правил — `secrets access show`. Значения не нужны.
3. Запускай через `secrets wrap --file FILE --use ITEM:F1,F2 OTHER:F3 -- python3 [ARGS]`. Один --use, несколько селекторов через пробел, поля через запятую. Пробелы в именах — в кавычках. Обёртка сама вставит FILE первым аргументом python3. Для прямого исполняемого файла опусти `-- python3`.
4. Если файл не разрешён, подготовь пользователю точную команду `secrets add ITEM:F1,F2 --file FILE`. Пользователь выполняет её и вводит мастер-пароль в своём терминале, даже при открытом демоне. Не создавай proposals, не угадывай назначения и не обходи отказ другим скриптом/интерпретатором.
5. При закрытом сеансе попроси выполнить `secrets unlock` в терминале. Пароль/сессию в чат не запрашивай. Для настоящих паролей псевдотерминал не используй.

## Выдача и разрешения

```sh
secrets wrap --file ~/Projects/tool/main.py --use my-app:token,username report-app:token -- python3
# Команда для выполнения пользователем:
secrets add my-app:token,username --file ~/Projects/tool/main.py --file ~/Projects/other/task.py
secrets access show
secrets access revoke my-app:token --file ~/Projects/tool/main.py
secrets access open my-app:token
```

--file проверяется по полному пути с разрешением симлинков. Контрольной суммы нет: изменение скрипта не отзывает разрешение. Whitelist интерпретатора/бинаря остаётся дополнительным ограничением; trust регистрирует сам CLI и не расширяет whitelist. Флаги интерпретатора перед файлом и запуск модуля -m не поддерживаются; подготовь обычный файл, если это входит в задачу.

Без --use выдача пуста, включая прежний wrap python3 app.py. Нет wildcard. Поле без правила доступно по явному запросу любому файлу. Поле с правилом — только перечисленным путям. Revoke последнего файла оставляет запрет всем; open отдельно снимает ограничение. Эти изменения требуют свежего пароля. После delete правила сохраняются, чтобы повторный импорт не расширил доступ.

Add с --file сохраняет существующие значения и дополняет список файлов; недостающие поля импортирует. Add ITEM --file FILE фиксирует текущие местные поля, а отсутствующую запись импортирует. Новые поля позже не наследуют это правило: до отдельной настройки они открыты для явного запроса. Для конкретных разрешений предпочитай явные ITEM:FIELDS.

Старый enforced остаётся дополнительным фильтром. `access reset-legacy` с паролем снимает его только после проверки новых правил. Не используй старый CLI или изменение конфига для обхода отказа.

## Диагностика без значений

`secrets status`, `secrets ls`, `secrets ls ITEM`, `secrets access show` показывают только метаданные. `secrets get ITEM FIELD` и `secrets ls ITEM FIELD` печатают настоящий секрет: для получения в контекст модели их не используй. Прямое чтение Bitwarden/Keychain/vault не заменяет обёртку.

ENV: item/field → ITEM_FIELD, неанглийские буквы и пунктуация → _. Начальная цифра сохраняется: 2service/api → 2SERVICE_API. Проверяй в приложении только наличие нужного имени или успешность операции; окружение и значения в журналы не выводи. Коллизии выбранных имён и управляющие ENV дают отказ до запуска. Версия3.2.0 имела ошибку цифровых имён, исправленную в3.2.1; записи ради обхода не переименовывать.

## Синхронизация и сеанс

Перед пользовательской командой встроен bw sync. Локальная команда lock пропускает его. Ошибку показывай; add/sync/apply при ней не пишут vault. После успешной команды (wrap — после завершения ребёнка) автоматически обновляются локальные значения в фоне, не чаще раза в минуту. Работает только с открытым демоном. Ошибка фонового обновления видна в следующем обращении/status; `secrets sync [ITEM [FIELD]]` проверяет и обновляет сейчас. Успех bw sync не доказывает обновление локального vault. Статус фона относится только к фоновому запуску; ручной sync сам по себе не очищает его прежнюю ошибку. provider_item_missing/provider_field_missing означают расхождение состава; Missing provider reference показывает только имя отсутствующей записи/поля: предложи точечный secrets sync ITEM, затем сверку имени/поля в Bitwarden. Ручной sync в терминале пользователя покажет отсутствующие записи/поля и предложит удалить значения [y/N]; Enter или отсутствие терминала сохраняет весь прежний vault. Агент показывает команду, но не подтверждает реальное удаление через псевдотерминал/pipe. Для выборочного удаления — точечный sync ITEM [FIELD]. Правила файлов после удаления сохраняются. Локальные записи и правила автоматически не удаляй; не объявляй всё синхронизированным по одному bw sync. Уже запущенное приложение сохраняет прежние ENV.

PIN удалён. Ключ и сессия — в RAM до lock/остановки демона; пароль стирается после ввода. Разблокировка не разрешает печатать значения. Отзыв сессии провайдером требует повторного unlock. Ошибка сети не разрешает менять VPN, proxy, TLS или сервер.

## Удаление местных значений

```sh
secrets delete my-app           # вся местная запись
secrets delete my-app token     # одно местное поле
```

Delete уже есть в CLI3.4. Удаляет только из локального vault этой машины, Bitwarden не меняет. При открытом сеансе выполняется сразу, без вопроса y/N и нового пароля; при закрытом требует обычную разблокировку. Агент выполняет только явно согласованное удаление конкретной записи/поля, не использует delete как автоматическое исправление ошибки sync. Для предложения исчезнувших данных пользователю — sync ITEM [FIELD] с подтверждением.

Правила файлов сохраняются и применятся при повторном add. Обычный sync/фон обновляет оставшийся подключённый состав и не возвращает удалённые значения; повторный add или manifest apply может импортировать их заново из Bitwarden. Для отзыва доступа файла без удаления значения — access revoke, для переноса пути — move. Отсутствующая запись/поле даёт ошибку без записи vault.

## Перемещённый файл

Если пользователь перенёс/переименовал скрипт, прочитай `secrets access show`, найди точный сохранённый старый путь и подготовь одну команду для его терминала:

```sh
secrets move ~/Projects/old-tool/main.py ~/Projects/new-tool/main.py
```

Новый файл должен существовать; старый искать на диске не нужно. При нескольких похожих путях уточни, какой переносить; имя main.py само по себе недостаточно. Move заменяет все связи OLD на NEW одной записью, показывает поля и требует свежий пароль. Значения, другие пути, ограничения legacy и правила удалённых полей сохраняются. Никакие файлы на диске не перемещаются. Затем исправь --file в согласованных вызывающих командах/навыках; по всему компьютеру замены не делай.

Если для старого пути нет правил, move не нужен: для открытых полей достаточно нового --file. Не создавай разрешения вместо отсутствующей перепривязки без решения пользователя. Для копии, которой доступ нужен одновременно со старым файлом, используй add --file; move отзывает старый путь. Реальные изменения пользователь подтверждает сам, пароль агент не вводит.

## Перенос и обновление

```sh
secrets manifest export ./secrets-manifest.json
secrets manifest apply ./secrets-manifest.json --dry-run
secrets manifest apply ./secrets-manifest.json
```

Manifest содержит имена, сервер/email и правила, без значений/ключей/сессий; новый файл0600. Apply сохраняет местные поля вне списка и правила; `--with-access` явно заменяет правила и требует свежего пароля. Флаг автоматически не добавляй. Dry-run не открывает vault, не читает значения и не запускает фонового обновления, но bw sync выполняется.

Manifest2 переносит полные пути: с with-access они должны существовать на целевой машине. Manifest1 не стирает правила файлов. Keys/vault разных машин не копировать друг на друга. Для новой машины setup, для существующей unlock. Несовпадение протокола — обновить CLI и daemon; изменения только CLI при протоколе2 могут устанавливаться без рестарта демона. Источник — репозиторий am-secrets.
